# Changelog - Yakuda Connect

### 🚀 v1.1.7

**Highlights:** Ein Abgleich mit WiVRn. Die **OpenVR-Auswahl arbeitet jetzt wie WiVRns eigenes Dashboard** — wählbar ist, was wirklich installiert ist · drei Einstellungen, die WiVRn nie gelesen hat, sind repariert bzw. entfernt (**refresh_rate**, **encoder-Schlüssel**) · der **USB-Zustand steht direkt bei den gekoppelten Headsets** („· USB" hinter dem Eintrag) · **Meta-Store-Link** für Quest-Nutzer unter dem APK-Installer.

> Diese Version ist gegen WiVRns Quelltext geprüft (`server/driver/configuration.cpp`,
> `server/active_runtime.cpp`, `dashboard/settings.cpp`, `CMakeLists.txt`) statt gegen
> Annahmen. Dabei kam heraus, dass drei Einstellungen jahrelang in eine Datei geschrieben
> wurden, in der WiVRn sie nie gelesen hat.

#### 🇬🇧 English

* **Changed** | **OpenVR compatibility now mirrors WiVRn's own implementation**: the dropdown offered a fixed "Auto / xrizer / opencomposite", and "Auto" quietly wrote the xrizer path into WiVRn's `config.json` — even where xrizer was not installed. It now works like WiVRn's dashboard: **Default** removes the key so WiVRn autodetects, every folder that actually exists is listed with its path, **Custom path…** opens a folder picker (trailing `/bin` and `/linux64` are stripped, same as WiVRn does), and **Disabled** writes real JSON `null` — the documented "do not touch OpenVR" state, not an empty string. The search list is WiVRn's own `OVR_COMPAT_SEARCH_PATH`, in the same order, so "Default" shows exactly which folder WiVRn would pick. Folders that distributions use but WiVRn does not search (Fedora's `/usr/lib64/…`) are offered too, marked as only working because the path is written explicitly. A folder without `bin/linux64/vrclient.so` is flagged — that is the file WiVRn itself checks for.
* **Fixed** | **`refresh_rate` was never a WiVRn setting**: WiVRn's server config has no such key — not in the current version, not in any version back to v0.22, and it never appeared in `docs/configuration.md`. Everything selected in the old dropdown was written into `config.json` and ignored. The refresh rate is chosen by the client in the headset (since WiVRn 25.12 all video settings live there). The dropdown is gone; in its place the Dashboard now shows which rates the detected headset supports and where to change them. The stale key is removed from WiVRn's config on the next save.
* **Fixed** | **The encoder setting was written under the wrong key**: up to WiVRn 25.11 it was `encoders` (a list) alongside `scale` and `bitrate`; since 25.12 it is `encoder`, and the other two are gone. The app always wrote `encoders` and even deleted `encoder` — so on current WiVRn the encoder choice did nothing at all. The installed server version is now detected via `wivrn-server --version` and the matching schema is written.
* **Added** | **USB state shown on the paired headsets**: a headset currently on the cable gets a "· USB" behind its entry in the paired list — the information sits on the device itself instead of taking up its own row. Below the list, a single compact line appears **only when something needs doing**: cable plugged in but USB debugging off, PC not confirmed in the headset, or adb missing. Detection reads `/sys/bus/usb/devices` directly — no root, no `lsusb` — and only calls `adb` when a headset is really on the bus. It polls only while the Dashboard is open, and only re-reads the paired list when something on the cable actually changed. "Refresh list" now checks both.
* **Changed** | **The "WiVRn dashboard is running" warning moved into the tooltip**: it used to sit permanently under the USB checkbox as a yellow strip, for a case that only applies while the dashboard is actually open. It is now appended to the checkbox's tooltip — right where you look before setting the option. The check itself runs in the background thread along with the USB scan, so the tooltip stays current without a `pgrep` on the GUI thread.
* **Added** | **Meta Store link under the APK installer**: installing over adb needs USB debugging and a developer account. Quest users can get WiVRn from the Meta Horizon Store instead; the link sits under the install button.
* **Internal** | New `core/usb_headsets.py` (no Qt, therefore testable) for USB detection and per-model refresh-rate profiles; the scan runs in its own thread so a slow `adb` cannot freeze the window. 42 new unit tests in `tests/test_openvr_usb.py`, including one that pins WiVRn's search path list so a silent drift gets caught.

### 🚀 v1.1.6

#### 🇬🇧 English

**Highlights:** A tidy-up release. **One AppImage** that starts on modern and older systems alike (FUSE 3 as well as FUSE 2) · the **firewall setup rebuilt along WiVRn's own implementation**, and it finally opens mDNS — without which the headset cannot find the PC at all · **dialogs stay readable on light desktop themes** · a **readable microphone list** and the VR fixes collected under Settings → VR & OpenXR.

* **Changed** | **One AppImage for FUSE 2 and FUSE 3**: instead of two files there is now a single `yakuda-connect-<version>-x86_64.AppImage`. It uses the type2 runtime, which has libfuse3 linked statically — so no `libfuse2` package is required — and which picks its mount helper from `$PATH` itself: the first setuid-root binary whose name starts with `fusermount`. That covers `fusermount3` on modern systems (Arch, CachyOS, Fedora 40+, Ubuntu 24.04+, Bazzite, SteamOS) and `fusermount` on older ones (Ubuntu 22.04 and earlier, Debian 11/12). The build script verifies afterwards that this runtime really is embedded, so a bad download cannot produce a file that fails on half the systems out there. Where FUSE is missing entirely, `--appimage-extract-and-run` still works.
* **Fixed** | **Firewall setup now matches WiVRn's own — and finally opens mDNS**: the button checked for `ufw` first and only looked at whether the binary existed. On Fedora, Nobara or Bazzite, where firewalld is in charge but ufw may still be installed, it wrote a ufw rule nobody reads and then reported success while the ports stayed shut. Detection now follows WiVRn's order (running firewalld first, then ufw) and, more importantly, also opens **5353/UDP for mDNS** alongside 9757 TCP/UDP — without mDNS the headset cannot find the PC at all, which is the most common "WiVRn doesn't see my computer" case. For firewalld the named `wivrn` service that WiVRn ships is preferred over raw ports, for ufw the same `/etc/ufw/applications.d/wivrn` profile is written as WiVRn's dashboard writes, so there are no duplicate rules. Everything runs in a single `pkexec` call now — one password prompt instead of two.
* **Added** | **nftables and iptables are recognised**: they are deliberately not modified automatically, because rules there depend on your table and chain names and a misplaced rule can cut the machine off the network. Instead the exact commands are shown with a copy button.
* **Fixed** | **"No firewall found" is no longer an error**: on Arch and CachyOS no firewall runs by default, so the red warning was wrong. It now says plainly that there is nothing to open, and points to the usual remaining suspects (router, guest WiFi with client isolation, VPN).
* **Fixed** | **Dialogs were unreadable on light desktop themes** (reported on GitHub): the app is dark throughout and set a light text colour for every widget, but message boxes are separate windows whose *background* came from the system theme. On KDE Breeze Light and similar, that meant light grey text on a light background — readable only by selecting it. Dialogs, menus, tooltips, dropdown popups and progress bars now bring their own background; contrast for dialog text goes from 1.3:1 to 13.4:1. The stylesheet is attached to the application instead of the main window, so dialogs without a parent window are covered too.
* **Fixed** | **German text in the English interface**: around 45 dialog and status texts were hard-coded in German — firewall errors, backup and restore dialogs, the GitHub sync, the file picker, the unpair prompt and the tool status lines. All of them now go through the translation files.
* **Fixed** | **Missing words in headings and buttons**: Qt reads a single `&` as a keyboard shortcut marker, so *"Tracking & Display & Connect Options"* appeared as *"Tracking Display Options"* and *"Notes & Information"* lost its ampersand. Affected widgets now use a helper that escapes it correctly.
* **Changed** | **Microphone list is readable again**: the dropdown under Settings → Audio showed raw node names (`alsa_output.usb-Generic_USB_Audio-00.HiFi__Speaker__sink.monitor`), all starting alike, with microphones, virtual nodes and monitors mixed together. It now shows the plain-text device name and is split into three groups — **microphones**, **virtual sources** (PipeWeaver nodes and their monitors) and **monitors** of the sound card, which are rarely what's wanted and therefore sit at the bottom. The raw node name is still available in each entry's tooltip.
* **Changed** | **OpenXR runtime switching and VR priority moved to Settings → VR & OpenXR**: both are one-off system repairs, not stream settings, and now sit next to the Steam fix and the OSCQuery fix. The Streaming tab keeps a note and a jump button so nobody has to go looking.
* **Added** | **"OpenXR / SteamVR fixes & performance" button on the Dashboard**: one click leads straight to Settings → VR & OpenXR. Those fixes were hard to find from the Dashboard, which is where people are when something doesn't start.
* **Removed** | **Hand Tracking and Full Body Tracking checkboxes on the Dashboard**: both have to be enabled in the headset itself; the checkbox in the app changed nothing but suggested otherwise. `hand_tracking` is no longer written to WiVRn's `config.json` either — an option that can only be set in WiVRn should not be overwritten from here. Existing configuration values are kept untouched.
* **Internal** | Firewall handling moved into its own `core/firewall.py` (no Qt, therefore testable) with 10 unit tests, including the Fedora case "firewalld active, ufw installed as well". The OpenXR/VR-priority box became `ui/vr_runtime_widget.py`, following the existing `queryfix_widget.py` pattern.

### 🚀 v1.1.5

#### 🇬🇧 English

**Highlights:** A stability and maintenance release. **Settings can no longer lose entries when saved** · every external command now has a **time limit**, so the window can't freeze when a package manager or headset hangs · a **log file** makes support cases traceable · **two AppImage variants** (fuse3 and legacy fuse2) so the app starts on both modern and older systems.

* **Fixed** | **Settings no longer lose entries**: saving used to rebuild the configuration from scratch and carry old entries over via a hand-maintained list. Anything missing from that list was silently dropped on the next save. The existing configuration is now the basis and only the relevant fields are replaced — unknown entries survive automatically.
* **Fixed** | **Configuration files can no longer be corrupted**: all JSON files are written to a temporary file first, flushed to disk and only then moved into place. A crash or power loss mid-write can no longer leave an empty or half-written file behind. This matters most for WiVRn's own `config.json`, which the app also writes. A file that is already damaged is set aside as `.broken` instead of being overwritten.
* **Fixed** | **The window can no longer freeze on external commands**: every call to an external program (package manager, `adb`, `pgrep`, `pactl`, …) now has a time limit. Previously a hanging `pacman` lock or a headset in standby froze the interface indefinitely.
* **Fixed** | **Closing the app no longer crashes**: only the cover download was awaited on exit — any other background task still running caused Qt to abort the process. All background tasks are now shut down in order.
* **Fixed** | **Duplicate German translation entry**: `backup_title` was defined twice with different text; the earlier one never took effect.
* **Added** | **Log file**: everything now also goes to `~/.cache/yakuda-connect/app.log` (rotating, max 1 MB). Started from a desktop icon there is no console, so error output used to be lost exactly when it was needed. For support cases: `YAKUDA_LOG_LEVEL=DEBUG yakuda-connect` gives more detail.
* **Added** | **Two AppImage variants**: the standard file uses the newer runtime with statically linked libfuse3 and needs no `libfuse2` (Fedora 40+, Ubuntu 24.04+, Bazzite, SteamOS). `-legacy-fuse2` is for older systems (Ubuntu 22.04 and earlier, Debian 11/12). `--appimage-extract-and-run` works with both.
* **Changed** | **FUSE detection for installed tools**: previously only `libfuse.so.2` was looked for, so AppImages with the newer runtime were needlessly unpacked to a temporary folder on every start. Now `/dev/fuse`, `fusermount`/`fusermount3` and both libfuse versions are recognised, with a fallback if the native start still fails.
* **Changed** | `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` are respected. If `~/.config/yakuda-connect` already exists it stays in use, so existing settings are not lost.
* **Changed** | **Version is maintained in one place** (`core/version.py`), kept in sync across app, PKGBUILD and update check by `scripts/bump_version.py`.
* **Added** | **Auto connect from USB** in the Dashboard tab, under *Tracking & Display & Connect Options*: the same option as in the WiVRn dashboard. When exactly one headset is found over USB and none is connected yet, WiVRn connects automatically. The value is written to WiVRn's own dashboard settings, so both applications always show the same state. If the dashboard is running, a note appears — it rewrites its settings on exit and would otherwise undo the change.
* **Changed** | **The app starts noticeably faster**: the package status in the Installation tab used to run one `yay -Q` *and* one `yay -Qu` per package — up to twelve process launches, half of them querying the AUR over the network, all on the GUI thread. The window only appeared once they finished. The package lists are now fetched once (two calls regardless of package count) and in the background, so the window is there immediately and the status lines fill in a moment later.
* **Added** | **Log buttons in Settings**: *Open log file* and *Copy log* under Settings → General. No more hunting for `~/.cache/yakuda-connect/app.log` when reporting a problem.
* **Changed** | **Translations moved to `locales/en.json` and `locales/de.json`**: the interface texts are no longer buried in a Python file. Contributing a language now means copying `en.json`, translating the values and opening a pull request — no Python knowledge required, and a typo can no longer stop the app from starting. Missing entries fall back to English automatically.
* **Internal** | `core/main.py` reduced from about 3,600 to roughly 2,100 lines; the Games and Tools tabs moved to `core/tabs/`. Automated tests added (smoke test extended from 5 to 11 checks, plus 16 unit tests) and CI set up, so these errors are caught before a release instead of by users.

**Highlights:** Fixes a bug that could stop **Steam from starting at all** on non-Arch distributions (reported on Nobara 44) · Restoring a backup no longer overwrites the package-managed folder `/usr/share/openxr` with foreign paths · New **OpenXR manifest check** that detects and repairs broken runtime files automatically at startup.

* **Fixed** | **Restore no longer breaks Steam on other distributions**: `XR/VR environment restore` used to run `rm -rf /usr/share/openxr` and copy the backup's `usr/openxr` folder in its place — including the **GitHub reference backup**, which was created on Arch. Library layouts differ per distribution (Arch: 64-bit in `/usr/lib/wivrn`, 32-bit in `/usr/lib32/wivrn`; Fedora: 64-bit in `/usr/lib64/wivrn`, 32-bit in `/usr/lib/wivrn`; Debian: `/usr/lib/x86_64-linux-gnu/wivrn`), so an Arch manifest on Fedora points at a **32-bit** library where a 64-bit one is expected. Steam's pressure-vessel container reads every manifest in `/usr/share/openxr/1` at startup and then aborts with ``gelf_getehdr(...): invalid `Elf' handle`` → steamwebhelper crash loop, Steam won't start. Backups now carry a `backup_meta.json` fingerprint (origin, distribution, library layout) and **system folders are only restored when the backup came from exactly this machine**. `/usr/share/openxr` is never wiped anymore — files are merged in, the old folder is kept as a timestamped `.bak` copy, and every runtime manifest is validated before it is written.
* **Changed** | **GitHub reference backup restores user configs only**: pulling the reference backup and restoring it now writes only `~/.config/openxr`, `~/.config/openvr` and `~/.config/wivrn`. System folders stay untouched — they belong to your package manager.
* **Added** | **Restored user manifests are adapted to your system**: after a restore, `active_runtime.json` is checked and its `library_path` rewritten to the WiVRn library actually present on this machine, instead of blindly keeping a foreign path. This makes the reference backup usable across distributions.
* **Added** | **OpenXR manifest check (Steam protection)**: on startup the app scans `/usr/share/openxr/1`, `/usr/local/share/openxr/1`, `~/.local/share/openxr/1` and `/etc/xdg/openxr/1` for runtime files whose library is missing or has the wrong bitness. If one is found you get a dialog explaining the Steam crash and offering a repair: paths are corrected where a matching library exists, otherwise the file is renamed to `.disabled` so Steam ignores it. Every file is backed up with a timestamp first. The *Steam Fix* button runs the same check.
* **Fixed** | **Bitness is now verified everywhere**: library detection checks the ELF class (32/64 bit) instead of just "file exists". Search order puts `/usr/lib64` first so Fedora/openSUSE resolve correctly, and a separate 32-bit resolver was added for `*.i686.json` manifests. Previously the Steam Fix could copy a wrong-architecture path from a broken system manifest straight into your `active_runtime.json`.
* **Note** | Backups created before v1.1.4 have no `backup_meta.json`. They still restore your user configs; system folders are skipped for safety. Create a fresh backup once to re-enable full restore on your own machine.
